# SakuSum（サクサム）要件定義書

## 1. アプリ概要

- **アプリ名:** SakuSum（サクサム）
- **サブタイトル:** サクッと合計が見える、1タップ大体家計簿
- **コンセプト:**
  1円単位の細かい入力にこだわらず、目安金額つきのカテゴリボタンを1タップで記録・集計し、今月のおおよその支出合計をストレスなく把握できるWebアプリ。

---

## 2. 対象ユーザー・到達ゴール

- **利用形態:** 個人専用（各ログインユーザーが自分のデータのみを記録・閲覧する）
- **主なターゲット:**
  - 細かいレシート入力や1円単位の家計簿が続かない個人ユーザー
  - ポートフォリオの閲覧者（アカウント作成の手間なく1タップ体験を試したい第三者）
- **到達ゴール:**
  ポートフォリオとして第三者に公開できる完成度を目指す。
  - Vercel 等での本番公開
  - アプリ紹介用のランディングページ（LP）
  - Firestore セキュリティルールによる適切なデータ保護
  - ローディング・エラーハンドリングの整備
  - 自動テストの導入（集計ロジック等の単体テスト中心＋主要フローの確認）

## 4. MVP 機能要件

### F1. LP（ランディングページ）＆ 認証（Firebase Authentication）

- **トップページ（`/`）に LP を配置:**
  - アプリの概要・特徴を紹介し、「登録なしで今すぐ試す（匿名ログイン）」「Google でログイン」の2つの導線を提供する。
  - すでにログイン済み（匿名ログインを含む）のユーザーが `/` にアクセスした場合は、アプリ画面へ自動リダイレクトする。
- **匿名ログインからのデータ引き継ぎ:**
  - 匿名ログインで利用しているユーザーが、後から Google アカウントと連携（リンク）することで、既存の記録データをそのまま引き継げる。
  - **エッジケースの扱い:** 連携先に「すでに別データが存在する Google アカウント」が選択された場合、MVP ではデータの統合（マージ）は行わず、確認ダイアログを表示したうえで既存アカウントへ切り替える（匿名時のデータは引き継がれない旨を明示する）。
- **ログアウト:**
  - 通常の Google ログインユーザーはいつでもログアウト可能。
  - 匿名ユーザーがログアウトしようとした場合は、「Google アカウント連携をしていないためデータが失われる」旨の警告を表示し、確認の上で実行する。

### F2. 1タップ支出記録 ＆ 誤タップ対策（Undo）

- **1タップ記録:**
  - 「カテゴリ＝目安金額」のボタン（例：`飲み物 ¥200`、`ランチ ¥1,000`）を1タップするだけで、現在日時で即座に支出を記録・集計へ反映する。
- **直後の取り消し（Undo）:**
  - 記録直後にトースト等で「元に戻す（Undo）」ボタンを表示し、誤タップを即座に取り消せる。
- **記録時点のスナップショット保持:**
  - 支出データには記録時点のカテゴリ名・金額を保持し、後からカテゴリの目安金額や名称を変更しても過去の支出合計・履歴が意図せず変わらないようにする。

### F3. 集計・ダッシュボード

- **合計表示:**
  - 「今月の合計」「今日の合計」を画面上部に見やすく表示する。
- **カテゴリ別内訳:**
  - 選択中の月におけるカテゴリ別の合計金額と構成比（割合バー）を表示する。
  - グラフ描画用ライブラリは使用せず、Tailwind CSS のみでシンプルに表現する。
- **月切り替え:**
  - 前月・次月への切り替えにより、過去の月の合計およびカテゴリ別内訳を確認できる。

### F4. 支出履歴の一覧・編集・削除

- **履歴一覧:**
  - 選択中の月の支出履歴を一覧表示する（新しい順）。
- **削除・編集:**
  - 各支出記録の削除ができる。
  - 各支出記録の**金額・日付・カテゴリ・メモ**を後から編集できる（編集時は1円単位を含む任意の金額を入力可能）。

### F5. カテゴリ管理（初期プリセット ＋ CRUD）

- **初期プリセットの自動生成:**
  - 初回利用時に以下のようなキリの良い目安金額つきカテゴリを自動生成し、開いてすぐ1タップ記録できる状態にする。
    - 飲み物（¥200）
    - コンビニ（¥500）
    - カフェ（¥600）
    - ランチ（¥1,000）
    - 外食（¥2,000）
    - 日用品（¥1,000）
- **カスタマイズ（CRUD）:**
  - ユーザーによるカテゴリの追加・編集（名前・目安金額・アイコン/色）・削除に対応する。

## 5. UI・非機能要件

- **モバイルファースト設計:**
  - スマートフォンでの片手1タップ操作を最優先に設計する。
  - PC 画面では最大幅を設けた中央寄せレイアウトとし、縦長でも崩れず見やすいUIにする。
- **金額入力・表示ルール:**
  - プリセット金額はキリの良い目安金額を推奨するが、アプリ側で100円単位丸め等の強制は行わず、合計額は実際の合計値をそのまま素直に表示する。
- **セキュリティ:**
  - Cloud Firestore のセキュリティルールを設定し、ログイン中ユーザー自身の `uid` 配下のデータのみ読み書き可能とする。
- **信頼性・UX:**
  - データ取得中・保存中のローディング表示、通信エラー時の分かりやすいエラーメッセージ表示を行う。
- **自動テスト:**
  - 集計ロジック・日付/月計算・入力バリデーションなどの純粋関数を中心に単体テストを実装し、品質を担保する。

## 6. MVP 外（将来機能 / Post-MVP）

MVP のスコープを明確に保ち、以下の機能は初回リリース後の拡張候補とする。

- 月ごとの予算設定・残額進捗ゲージ
- チャートライブラリ（Recharts 等）を用いた円グラフ・日別棒グラフ
- 家族・パートナーとの家計簿共有機能
- 匿名利用データと既存 Google アカウントデータの統合（マージ）機能
- 定期支出・固定費の自動登録
- CSV エクスポート機能
- PWA 対応・オフライン記録機能
